### 2026-08-13 — composer 固底结构存在但坐标仍跳跃/闪烁（TUI-3 重开 → P1 ACCEPTED WITH LIMITATIONS）

- 场景：Motto alt-screen 日常 dogfood；transcript streaming 与底部状态变化期间观察 composer。
- 现象：composer 已位于独立 bottom dock，但仍会上下跳跃并出现闪烁；旧验收只证明最终静态
  画面沉底，没有证明相邻 frame 的 composer 坐标稳定。
- 用户证据：2026-08-13 直接回报；当时未独立取得连续 frame 捕获（中间态，处置见下）。
  **同日后续只读复验已取得 80×24 逐帧 trace，footer 替换接缝机制经确定性测试机械复现**；
  端到端生产 rebind 链未跑通（NOT_TESTED），ROOT_CAUSE 为 STRONGLY_SUPPORTED——旧句
  「具体触发频率与唯一根因 NOT TESTED」已被取代。
- 已证结论（footer 替换接缝机制；RecordingTerminal 逐帧 trace；权威报告
  `/private/tmp/motto-tui4-s3-compact/TUI-3-P0-FRAME-STABILITY-report.md`，机制经源码互证）：
  - footer 1→2→3→1 ↔ composer y20→y19→y18→y20（bottom 23→22→21→23）；belowEditor widget
    显隐 ↔ composer y20→y19→y20；editor 多行向上增长、bottom 恒 23（底边锚定）。
  - 真实链路 = `resetExtensionUI()` → `setExtensionFooter(undefined)` 恢复原生两行 footer →
    extension bind（异步 await）→ `registerFooter` 重新注册 Motto 单行 footer；异步间隙若被
    render，原生两行中间态可见 → composer 先上移再回位 = 用户回报的「上下跳跃、闪烁」。
  - 同 tick 的 footer 1→2→1 只产生 1 次 flush（COALESCE_SAME_TICK=1）；根因不在同 tick，
    在 reset/rebind 的异步间隙。
  - **footer 替换接缝机制机械复现（返工新增）**：`packages/coding-agent/test/
    tui3-p0-rebind-frame.test.ts` 驱动 `resetExtensionUI → 原生两行 footer → 单行 footer`
    （真实原型方法 + 真实 `FooterComponent` + 真实渲染管线 + RecordingTerminal 80×24），
    受控异步间隙下捕获 footer 1→2→1、composer y20→y19→y20 中间可见帧（2/2 通过）；
    mutation proof：原子替换后中间帧消失、断言翻转（早期锚定 mutation 已被本测试取代）。
    **这是 FOOTER_REPLACEMENT_SEAM_MECHANISM 的 PROVEN，非完整生产 rebind 链**——
    END_TO_END_RUNTIME_REBIND NOT_TESTED（未驱动 runtimeHost→rebindCurrentSession→
    bindExtensions→session_start；测试内 dummy footer，未过完整 init() 布局，20ms 为
    wall-clock）。该测试即最小修复单验收测试，修复落地后翻转断言。修复方案经用户裁定收紧
    为 `MOTTO_CUSTOM_FOOTER_HEIGHT_CONTRACT = 1`（决策单 §9）：custom→custom 全程
    1→1、无 native 中间帧；custom→native / native→custom / bind 失败回落均为一次原子
    拓扑转换；Motto footer 自行投影 extension statuses；core 原子接缝含生态 fallback。
- 源码候选链（中间态）：dock 使用 `basis: "auto"`；pending/status/widgets/editor/footer 的
  intrinsic height 均参与布局；`resetExtensionUI()` 先恢复原生两/三行 footer，Motto
  extension 随后再注册单行 footer——上述结论即此链的机制复现（接缝 PROVEN；端到端链
  NOT_TESTED）。
- 开源对照：Codex CLI 采用同源 `desired_height` + bottom pane + synchronized frame；OpenCode
  采用 transcript 弹性区 + 非收缩 prompt/footer；Grok Build 未核实具体布局函数，只作行为参照。
- 处置：P1 已按 `MOTTO_CUSTOM_FOOTER_HEIGHT_CONTRACT = 1` 实现：custom→custom 保持 1→1，
  无 custom/bind 失败或取消时一次原子回落原生 footer；reload 收尾强制提交最终 footer 帧；
  extension statuses 同行投影且窄宽先于 TPS 降级。不建第二套 composer、不用 timer debounce。
  终态 **ACCEPTED WITH LIMITATIONS**；完整 runtimeHost 端到端链仍为 NOT_TESTED。

### 2026-08-13 — 成功内置工具在真实会话中不收敛为目行（P0 D1 → TUI-1-S3-LIVE）

- 场景：MOTTO-TUI-FULL-SESSION-P0 真实 Ghostty 全会话 dogfood——连续 bash/write/read 成功
  工具后，chat 流内工具卡全部为原生全卡（`$` 命令 + 输出预览 + Took），与 recap 目行构成
  tool+target 双份呈现；recap 面成功静默成立，chat 流内压缩缺失。
- 扩展/动作：TUI 内置工具渲染（ToolExecutionComponent S3）+ interactive-mode 接线。
- 目标应用/环境：Ghostty 1.3.1 · macOS 26.5.2 · Motto（pi 0.84.1 + patchset）。
- 现象：成功内置工具未收敛为 S3 低对比目行（与「成功静默」总则 I2 相悖）。
- 可逆性：无破坏；纯呈现问题。
- 疑似根因：interactive-mode `getRegisteredToolDefinition` 直通 `session.getToolDefinition`，
  而 `_toolDefinitions` 收容全部工具（含 source=builtin），组件误判内置工具遭自定义覆盖，
  `isSuccessIndexLine` 恒假；无头基线以 `toolDefinition=undefined` 构造组件，记录的是组件
  语义而非实机接线——基线绿 ≠ 实机绿。
- 处置：**已修**（TUI-1-S3-LIVE，code commit `b27911c9c`）——按 canonical
  `sourceInfo.source === "builtin"` 判定接线，恢复实机单行目行；失败/流式/展开/自定义覆盖
  边界保持。

  `docs/reviews/2026-08-13-handoff-tui-full-session-p0.md` §三.1、
